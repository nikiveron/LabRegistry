# LabRegistry

Внутренний инструмент для регистрации и контроля объектов, поступающих в испытательную лабораторию.

Проект состоит из серверной части на **ASP.NET Core** с хранением данных в **PostgreSQL** и десктопного клиента на **WPF**.

## Реализовано

### Серверная часть

* REST API для работы с объектами проверки:

  * получение списка с поиском, комбинируемыми фильтрами и встроенной пагинацией;
  * получение объекта по `Id`;
  * создание объекта;
  * изменение результата проверки и примечания;
* Валидация входных данных с использованием FluentValidation.
* Регистронезависимый поиск по части наименования.
* Обработка ошибок с использованием соответствующих HTTP-кодов 400 и 404.
* PostgreSQL в качестве хранилища данных.
* EF Core для работы с БД.
* Создание схемы БД с помощью EF Core Migrations.
* Строка подключения хранится в конфигурации.
* Асинхронное выполнение операций с БД и HTTP-запросов.

### WPF-клиент

* Однооконный интерфейс для работы с объектами проверки.
* Таблица объектов с:

  * поиском по наименованию;
  * фильтрацией по типу;
  * фильтрацией по результату;
  * постраничной навигацией.
* Форма создания нового объекта.
* Изменение результата проверки и примечания выбранного объекта.
* Взаимодействие с данными выполняется исключительно через REST API.
* Реализовано разделение представления и логики по принципам MVVM.
* Сетевые и серверные ошибки отображаются пользователю без завершения приложения.
* Все длительные операции выполняются асинхронно, поэтому интерфейс не блокируется во время запросов.

### Дополнительно

* Модульные тесты для валидаторов и ключевой логики обработчиков.
* Docker Compose для запуска PostgreSQL и серверной части.
* Постраничная выдача списка объектов.

## Архитектурные решения

Серверная часть разделена на слои **Domain, Application, Infrastructure и Server**, что позволяет отделить бизнес-логику, доступ к данным и HTTP-слой.

Для разделения операций чтения и изменения данных используются команды и запросы с обработчиками на базе MediatR. Валидация вынесена в отдельные валидаторы, а работа с PostgreSQL — в репозиторий. Это упрощает тестирование и снижает связанность прикладной логики с инфраструктурой.

WPF-клиент взаимодействует с сервером через отдельный API-клиент и не имеет прямого доступа к базе данных. Логика представления отделена от UI с помощью MVVM.

Постраничная выдача реализована на стороне сервера, чтобы при увеличении количества объектов клиент не загружал весь набор данных.

## Требования

Для запуска проекта необходимы:

- .NET 8 SDK;
- Windows, так как клиент реализован на WPF;
- Docker Desktop — для запуска PostgreSQL и серверной части.

Клиент и сервер используют .NET 8.

## Запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/nikiveron/LabRegistry
cd LabRegistry
```

### 2. Настроить переменные окружения

В корне проекта создать файл `.env` с содержимым:
```dotenv
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=labregistry_db

PGADMIN_DEFAULT_EMAIL=postgres@localhost.com
PGADMIN_DEFAULT_PASSWORD=postgres
```

### 3. Собрать и запустить серверную часть и PostgreSQL

В корне проекта выполнить:

```bash
docker compose build
docker compose up -d
```

### 4. Запустить WPF-клиент

Через Visual Studio или в отдельном терминале:

```bash
dotnet run --project src/LabRegistry.Client
```
